# 通用回答系统：移除深度档位，重建质量优先的 Full

本稿对应当前实现。历史 Fast/Full 首轮实测保存在 artifacts/answer-engine；本轮质量验收保存在 artifacts/full-quality-v2。实际正文、蓝图和耗时判断见该目录验收报告，不以 complete 代替质量结论。

## 默认行为与入口

- 默认 Fast＋low；Full 默认 high。CLI 和 ANSWER_REASONING_EFFORT 显式值优先，模型未知/不支持所选档位时省略参数。
- 删除 --depth 与运行时四档深度字段；旧参数在检索前报错，历史 JSON 深度字段读取时忽略。
- 简要/详细是自然语言偏好，Planner 按用户任务和基础决定必要关系、例子和章节，不强制固定章节或字数。
- 支持 WHAT、WHY、HOW、COMPARE、DEBUG、LOCATE、GENERAL。普通入口默认 teach；旧显式模式保留其流程，移除深度依赖。
- single_stream 映射 Fast，v3 映射 Full；与 --profile 矛盾时报错。multi_pass/explain/legacy 不与新 profile/effort 混用。

```powershell
uv run devcontext ask "问题" --profile fast --debug
uv run devcontext ask "详细解释项目为何要使用责任链校验。" --profile full --debug
uv run devcontext ask "问题" --profile full --reasoning-effort high --hard-timeout 900 --perf-json artifacts/full.json
```

## 全流程质量契约

Full 检索继续使用既有索引、EvidenceWorkspace 和完整覆盖流程。WHAT 查职责和实际调用，WHY 查技术效果、装配/执行与维护取舍，HOW 查同一次请求的状态写入、事务范围和失败处理。接口、注释或计划不能代替执行体与实际调用证据；检索缺口进入 Planner，不新增独立分类调用。

Planner 一次调用内按依赖推进：问题焦点与读者起点 → 学习目标 → 结论及前提 → 解释骨架 → 整体关系地图 → 场景 → 章节教学增量/主要展开位置 → 整体自检。默认基础 Java，用户背景优先。

- WHY：原方案可工作，当前设计改变什么条件/依赖，为什么有效、有什么成本。七槽保存因果取舍，不把七槽变成七章。
- HOW：起始状态、动作、结果、条件、依赖和故障。PRECEDES 与 DEPENDS_ON 分开；from_step 指向当前单元。失败必须有触发及 BRANCH_FROM。尾部保证与 UNKNOWN 边界分开。
- WHAT：定义职责、解决的问题、相邻关系、具体例子和适用边界。
- 其它意图使用共同解释单元；定位不凑完整教学模板。

统一解析器检查目标、骨架、checkpoint 覆盖；所有引用有效；学习增量非空且前后不同；Claim 主要展开章节存在；场景世界不能互相延续，正常路径不能接在失败状态后；UNKNOWN 不能当成已建立保证。结构错误最多一次 Planner 重试，附具体原因，不增加 Reviewer。

Organizer 汇总 owned、may_reference、骨架、checkpoint、整体地图及区别的全部 Claim 依赖，全局去重。后节只携带需要承接的前节结论，避免复制全部前文。必要材料不完整时将相关项目结论缩为 UNKNOWN，并同步移出已建立保证；必要材料超窗口明确失败，不裁掉证明链。概念段允许无引用。

Writer 根据意图和场景类型选择专用契约。第一节先回答业务问题、建立整体关系，后文才引入源码标识符；核心段将动作、状态结果、有效原因、成立条件连起来。例子落实 checkpoint；正常路径先完整，故障回到分叉点。边界贴近机制，避免最后审计对账；同一收益只在 owner 章节完整展开。

完整虚构 WHY/HOW/WHAT 样本包含输入、蓝图、实际 Organizer 包、Writer 消息与正文；其它意图紧凑示范。每次仅加载对应样本，不能迁移其事实。可复用导出位于 docs/examples/full-quality-v2。

## 时间、预算与交付

正常回答模型调用仍为 Planner、Writer 两次，无 Reviewer。检索阶段保持 low。Full 质量优先，无默认总截止；外部调用仍有有限超时。

| 配置 | 默认 |
|---|---:|
| ANSWER_PROFILE | fast |
| ANSWER_REASONING_EFFORT | 未设置，Fast low / Full high |
| ANSWER_HARD_TIMEOUT_SECONDS | 未设置 |
| ANSWER_FAST_LATENCY_TARGET_SECONDS | 45 |
| ANSWER_FULL_LATENCY_TARGET_SECONDS | 300 |
| ANSWER_PLANNER_TIMEOUT_SECONDS | 180，Fast |
| ANSWER_WRITER_TIMEOUT_SECONDS | 240，Fast |
| ANSWER_FULL_PLANNER_TIMEOUT_SECONDS | 300 |
| ANSWER_FULL_WRITER_TIMEOUT_SECONDS | 600 |

软目标仅观测，不中断或降档；显式硬截止从请求入口起包含检索与重试。Planner 最多重试一次；Writer 首节前可重试一次，发布后不重放。Full 两阶段输出上限 min(32768, 模型项目上限)，Fast Planner min(8000, 上限)、Writer min(16000, 上限)。预算可能含推理消耗，不等于正文字数。

complete 是正常结束且计划章节全部交付、协议闭合；partial 是已发布但中断或缺章；failed 是未发布且无法继续。token 截断不能算 complete。debug 展示实际各阶段、模型与请求/实际档位、首节及总耗时。

## 验证与实际质量判断

自动检查覆盖深度移除、历史读取、档位优先级与真实省略、七种意图、目标/骨架/场景依赖、证据范围缩减、窗口失败、超时和部分交付。旧相关回归继续运行。

真实 Full 三题：责任链是什么及业务关系；为什么使用责任链；购票占座如何保证数据一致性。保存真实正文、计划、证据包和耗时；WHY 与当前旧 Full 及上一版 V3 对照，HOW 与旧 V3 对照。

检查基础 Java 读者能否复述定义和原因、重建正常过程；准入、数据库裁决、本地事务和跨系统失败处理是否分清；是否减少组件列表、重复收益和审计语言。首轮失败或不清楚时保留结果，定位具体阶段，只复跑受影响题。三题不能证明所有问题均改善。
