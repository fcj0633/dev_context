> 任务性质：源码学习 / 实现导读 / 执行链路分析
> 目标读者：项目作者本人
> 当前基础：熟悉 Java 后端，理解基础 RAG / Chunk / Embedding / 向量检索概念，但尚未完全掌握当前 DevContext 的具体实现细节
> 核心目标：从“知道项目用了哪些技术”提升到“能够跟踪一条真实数据流、解释关键源码、预测修改后的行为”

---

# 0. 本任务的最终目标

当前我已经知道项目在高层上采用：

```text
Java
→ JavaParser
→ Code Chunk

Markdown
→ Heading-aware Chunk

Chunk
→ Keyword / Vector Retrieval

Keyword + Vector
→ RRF

Retrieval
→ Benchmark Evaluation
```

但是仅知道这些高层概念是不够的。

本轮任务不是继续生成一份“架构总览”。

你需要生成一套**面向源码学习的详细导读文档**，帮助我真正理解：

```text
一个 Java 文件
究竟经过哪些函数
变成数据库中的一行？

一个 Markdown 文件
究竟怎样变成 DOCUMENT_SECTION？

一个 Chunk
究竟怎样产生 keyword_text 和 embedding_text？

到底按什么顺序执行？

一个 Query
进入 Keyword Retriever 后

Vector Search 的 SQL 到底如何工作？

Keyword / Vector 两个 Top-N
究竟怎样被 RRF 合并？

```

最终目标不是让我背源码，而是让我拥有：

```text

→ Output
```

的完整脑内执行模型。

