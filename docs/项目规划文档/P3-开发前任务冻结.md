# 4. 当前已经完成的三项关键调研

## 4.1 Continue

Continue 调研主要解决：

```text
Repository
↓
Chunk
↓
Index
↓
Retrieval
```

整体工程分层问题。

核心启发包括：

* Repository 不应该直接进入 Embedding；
* Chunk 应作为独立知识层；
* Keyword 和 Vector 可以基于同一批 Chunk 建立不同索引；
* 不同检索方式解决不同问题；
* 增量索引可以后移；
* DevContext 不需要复制 Continue 的全部 IDE / 多语言复杂度。

---

## 4.2 JavaParser

JavaParser 调研主要解决：

```text
Java Source
↓
AST
↓
Structured Code Chunk
```

已经形成的方向：

```text
METHOD
    作为主要 Code Chunk

CLASS
    使用摘要 Chunk

CONSTRUCTOR
    单独 Chunk
```

需要提取：

```text
package_name
class_name
method_name
signature
annotations
javadoc
start_line
end_line
content
```

源码 Content 原则：

```text
JavaParser Range
+
原始 Source File
↓
原始源码切片
```

而不是：

```text
Node.toString()
```

V1 不引入：

```text
SymbolSolver
Reference Resolution
Call Graph
```

---

## 4.3 RAGFlow

RAGFlow 调研主要解决：

```text
Chunk
↓
Retrieval
↓
Hybrid
↓
Rerank
↓
Evaluation
```

关键结论：

```text
不同数据类型
→ 不同 Chunk Strategy
```

```text
Identifier / Symbol Query
→ Keyword Retrieval 更重要
```

```text
Natural Language Why / How
→ Vector Retrieval 更重要
```

```text
MIXED
→ Keyword + Vector
```

DevContext P0 采用：

```text
Keyword
+
Vector
+
RRF
```

而不是 RAGFlow 的 weighted sum。

Evaluation 必须独立于 LLM Generation。

不要：

↓
